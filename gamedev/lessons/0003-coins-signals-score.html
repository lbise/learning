Nodes and resources: the Size mystery

This answers your question from Lesson 2: why Size wasn't on the node.

In Lesson 2 you had to click into BoxShape3D to find Size. That's because Godot has two kinds of thing. “Nodes give you functionality … Resources are data containers. They don't do anything on their own: instead, nodes use the data contained in resources.”

NodeResource
ExamplesCollisionShape3D, MeshInstance3D, Camera3DBoxShape3D, BoxMesh, StandardMaterial3D, a script, a .tscn
LivesIn the scene treeInside a node's property (the clickable field in the Inspector), or as a file
HoldsWhere something is, and what it doesData: how big, what colour, what shape

In embedded terms, a resource is like a const config struct that several drivers point to. Edit it once and everyone using it sees the change. That's why colouring one crate in Lesson 2 coloured them all.

Area3D: detect, don't block

A coin should notice the player without stopping them, which is exactly what Area3D is for. When a body enters it, the area emits body_entered(body): “Emitted when the received body enters this area.”

Signals: callbacks with zero coupling

The docs point to the observer pattern in Game Programming Patterns. It's a good read for a programmer.

“Signals are a delegation mechanism built into Godot that allows one game object to react to a change in another without them referencing one another.” You already know the shape of this: it's registering a callback, like attaching a handler to an interrupt. The emitter fires and doesn't care who is listening.

Today you'll use both kinds:

  • Built-in signal: the coin listens to its own body_entered.
  • Custom signal: the coin declares signal collected and emits it. The world listens and updates the score. The coin never needs to know a score or a HUD exists.
World (Node3D) ← world.gd: counts coins, updates label
├─ HUD (CanvasLayer)
│  └─ ScoreLabel (Label)
├─ Coins (Node3D)                 ← just a folder
│  ├─ Coin  ─── collected ──▶ World._on_coin_collected()
│  ├─ Coin
│  └─ Coin
├─ Player, Floor, Crates, DirectionalLight3D (from Lesson 2)

A CanvasLayer draws its 2D children on a separate layer, on top of the 3D view. That makes it the standard home for a HUD.

One ordering fact makes the world script work: “If the node has children, their _ready() callbacks get triggered first, and the parent node will receive the ready notification afterwards.” So when World._ready() runs, every coin already exists and can be connected.

Build it

A. The coin scene

  1. New scene, root Other Node → Area3D, renamed Coin.
  2. Add a child CollisionShape3D with New SphereShape3D (default radius 0.5 m).
  3. Add a child MeshInstance3D with New CylinderMesh. Click the CylinderMesh field to expand it (it's a resource) and set Top Radius and Bottom Radius to 0.4 and Height to 0.1. On the node, set Rotation x = 90 so the coin stands upright.
  4. Still inside the CylinderMesh resource, set Material → New StandardMaterial3D. Click it to expand and set Albedo → Color to gold. Optionally set Metallic to 0.8.
  5. Attach a script to Coin (coin.gd) with the code below. Save as coin.tscn.

extends Area3D

signal collected   # custom signal: "I was picked up"

func _ready() -> void:
	body_entered.connect(_on_body_entered)   # built-in signal → my handler

func _process(delta: float) -> void:
	rotate_y(3.0 * delta)                    # purely visual spin

func _on_body_entered(body: Node3D) -> void:
	if body.is_in_group("player"):
		collected.emit()
		queue_free()                         # delete me at the end of this frame

queue_free() “queues this node to be deleted at the end of the current frame”, which is safer than freeing it in the middle of a signal callback.

B. Tag the player

  1. Open player.gd and add this above _physics_process. It puts the player in a group, a named tag the coin can check, so enemies or rolling barrels won't pick up coins later: 
    func _ready() -> void:
	add_to_group("player")

C. Coins and HUD in the world

  1. Open world.tscn. Add a plain Node3D child of World named Coins. It's just a folder.
  2. Drag coin.tscn from the FileSystem dock onto the Coins node, so it becomes its child. Set Position y = 1. Press Ctrl+D to make 5–8 coins and spread them out. Put at least two on top of crates (y = 2), and one on your 2 m stack (y = 3) as the hard one.
  3. Add a CanvasLayer child of World named HUD, and give it a Label child named ScoreLabel. In the Label's Inspector: Layout → Transform → Position = (20, 20), and Theme Overrides → Font Sizes → Font Size = 32.
  4. Attach a script to World (world.gd) with the code below. Save and press F6.

extends Node3D

@onready var score_label: Label = $HUD/ScoreLabel   # looked up once _ready runs

var score := 0
var total := 0

func _ready() -> void:
	var coins := $Coins.get_children()   # coins are already ready (children first)
	total = coins.size()
	for coin in coins:
		coin.collected.connect(_on_coin_collected)
	update_label()

func _on_coin_collected() -> void:
	score += 1
	update_label()

func update_label() -> void:
	if score == total:
		score_label.text = "You found all the coins!"
	else:
		score_label.text = "Coins: %d / %d" % [score, total]

$HUD/ScoreLabel is a node path relative to this node, so it walks the scene tree. @onready delays the lookup until the node is ready.

Experiments: predict first, then run

1. In coin.tscn, change the Material's colour to red and save. How many coins change? Why?

Show answerAll of them. Every coin instance uses the same CylinderMesh resource, and the Material resource inside it. One piece of data with many users, like the shared config struct.

2. Comment out add_to_group("player") in player.gd and run. What happens when you touch a coin? Then put it back.

Show answerNothing. body_entered still fires (put a print(body) in the handler to see it), but the group check fails, so nothing is collected. Signals firing and your logic reacting are two separate things, and checking each one is how you debug them.

3. Drag one extra coin onto World directly instead of onto Coins. What will the counter show, and what happens when you pick that coin up?

Show answerThe total is one short, and picking that coin up does nothing to the score. It still vanishes, because its own script works, but World only connected the children of Coins. The scene tree's structure is part of your program's logic.

Playtest with your kids

This is the part that counts. Real players are the feedback loop no lesson can fake.

  1. Sit them down. Tell them only “find all the coins”. Don't explain the controls.
  2. Watch silently for 5–10 minutes. Don't help unless they're truly stuck.
  3. Write down one thing that confused them and one thing that delighted them.
  4. Bring both to the next session. They'll steer what we build next.
