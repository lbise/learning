Warm-up: from memory

In three sentences: how does a mouse movement end up changing pivot.rotation.y?

Show answerThe OS reports the motion and Godot wraps it in an InputEventMouseMotion. It passes through _input and the GUI, and if nothing consumes it, it reaches _unhandled_input(event). There you check its type and add event.relative.x × sensitivity to the yaw: you're accumulating deltas, like encoder ticks.

From Lesson 3: why does the coin emit a signal instead of updating the label?

Show answerSo the coin doesn't need to know a HUD exists (low coupling). Anything can listen, or nothing.

From Lesson 2: why is gravity multiplied by delta, but velocity isn't?

Show answerYou integrate acceleration into velocity yourself. move_and_slide() integrates velocity into position using the physics delta.

① Worked example: importing and animating

The asset

Quaternius' pack page states “License CC0”, and the itch page says “Free to use in personal, educational and commercial projects.”

We'll use Quaternius' Universal Animation Library (Standard): a 1.83 m mannequin with 43 animations in a single .glb file. It's CC0, so it's fine for a Steam game, and it's a grey mannequin on purpose: later you can model your own character in Blender for this same skeleton.

Godot treats a .glb as a scene. Drop it in your project and it gets imported. Then you instantiate it exactly like crate.tscn. The docs recommend glTF as the format: “glTF 2.0 (recommended)”. Here's what's inside this one, with paths checked in Godot 4.7.2:

UAL1_Standard (Node3D)    ← rename instance to "Character"
├─ Armature (Node3D)
│  └─ Skeleton3D            65 bones
│     └─ Mannequin          the skin (MeshInstance3D)
└─ AnimationPlayer         43 clips: Idle, Walk, Sprint, …

Three facts that will bite you

FactConsequence
Looping comes from the clip name. The docs: “Animation clips … that start or end with the token loop or cycle will be imported as a Godot Animation with the loop flag set.”The file has Walk_Loop, Idle_Loop and so on, and Godot strips the suffix. So in code it's "Walk", not "Walk_Loop". Clips without the token, like Jump_Start, play once and stop.
Imported models face +Z. MODEL_FRONT is (0, 0, 1), but your facing code from Lesson 4 assumes the front is −Z.Rotate the character instance 180° inside Model. The facing maths stays unchanged.
play() on the clip that's already playing continues it. (I tested this: calling play("Walk") every frame keeps advancing smoothly.)You can safely call play() every physics tick with the animation you want. One catch: a finished non-looping clip restarts.

play(name, custom_blend): the second argument is a cross-fade time in seconds. Without it, switching from Walk to Idle snaps instantly. Each clip is an Animation resource held by the player node: the same node/resource split as in Lesson 3.

Set it up (new editor steps, so full instructions)

  1. Open the itch.io page → Download Now → skip the payment prompt (the Standard version is free) → download Universal Animation Library[Standard].zip.
  2. Unzip it. Copy Unreal-Godot/UAL1_Standard.glb (not the _RM one, which has root motion baked in) into a new models/ folder in your project. Godot imports it automatically.
  3. Optional, but fun: double-click the .glb in the FileSystem dock to open Advanced Import Settings. You can preview every animation there.
  4. Open player.tscn. Drag UAL1_Standard.glb onto the Model node. Rename the new node Character and set its Rotation y = 180.
  5. Delete the old capsule MeshInstance3D and the Nose under Model. Keep the CollisionShape3D on Player: physics still uses the capsule, because collision and visuals are separate.

The code

Add a reference and a blend setting at the top of player.gd, call update_animation as the last line of _physics_process, and add the function:

@export var anim_blend := 0.2   # seconds of cross-fade between clips
@onready var anim: AnimationPlayer = $Model/Character/AnimationPlayer

# … at the very end of _physics_process, after move_and_slide():
	update_animation(direction)

func update_animation(direction: Vector3) -> void:
	if not is_on_floor():
		anim.play("Jump", anim_blend)      # the airborne loop
	elif direction.length() > 0.01:
		anim.play("Walk", anim_blend)
	else:
		anim.play("Idle", anim_blend)

The path $Model/Character/AnimationPlayer reaches into the imported scene. That works fine in code. The editor only hides those children unless you enable “Editable Children”.

Read update_animation as a priority list: airborne beats moving, and moving beats standing. It runs after move_and_slide(), so is_on_floor() reflects this tick's movement.

Predict, then try

1. Set the Character's Rotation y back to 0 and walk around. What do you see?

Show answerMoonwalking. The legs walk forward while the body moves backwards, because the model's front is +Z and your facing code points −Z at the movement direction. Set it back to 180.

2. Change "Walk" to "Walk_Loop". What happens?

Show answerAn error in the debugger like “Animation not found”, and the character stops animating while moving. Godot renamed the clip during import. When a name doesn't work, check the real list: double-click the .glb to see it in Advanced Import Settings, or print(anim.get_animation_list()).

3. Set anim_blend to 0.0 in the Inspector, then to 1.0. How does each feel?

Show answerAt 0, each switch snaps between poses. At 1.0 everything feels floaty: the character is still half-walking a second after stopping. Values around 0.1–0.25 s usually feel right. This is game feel, and tuning it is half the craft.

② Completion: the sprint animation

Your sprint from Lesson 5 makes the character faster, but it still uses the walk animation. The clip "Sprint" exists. Fill in the TODOs:

# in _physics_process: you already compute this for speed. Keep it in a variable
	var sprinting := Input.is_action_pressed("sprint")
	# …
	update_animation(direction, TODO 1)

func update_animation(direction: Vector3, sprinting: bool) -> void:
	if not is_on_floor():
		anim.play("Jump", anim_blend)
	elif direction.length() > 0.01:
		# TODO 2: "Sprint" while sprinting, otherwise "Walk"
	else:
		anim.play("Idle", anim_blend)

Done when: holding Shift while moving switches to a running animation, standing still with Shift held still idles, and jumping while sprinting shows the airborne clip.

Solution

Show solution 
	update_animation(direction, sprinting)

	elif direction.length() > 0.01:
		if sprinting:
			anim.play("Sprint", anim_blend)
		else:
			anim.play("Walk", anim_blend)
Tested in Godot 4.7.2 without a window: standing gave Idle, holding W gave Walk, W + Shift gave Sprint, then Jump while airborne and Idle after landing.

③ On your own: the victory dance

Your kids collect the last coin, and the character stops and dances (the clip is "Dance"). Everything you need comes from Lessons 2–3. The only new call is anim.play, which you've just used.

  1. When the last coin is collected, the character plays "Dance" and keeps dancing.
  2. While dancing, WASD and jump do nothing, but gravity still works.
  3. The coin and the player still don't know about each other. The world tells the player.
  4. The player is found without a hard-coded node path.

Hint 1: why the dance stops after one frame

Show hintIf you just call anim.play("Dance") from outside, the next tick's update_animation immediately plays "Idle" over it. The player needs to know it's celebrating, with a flag it checks early in _physics_process.

Hint 2: finding the player from the world

Show hintThe player is already in the "player" group (Lesson 3). get_tree().get_first_node_in_group("player") returns it.

Solution

Show solution 
# player.gd
var celebrating := false

func celebrate() -> void:
	celebrating = true
	anim.play("Dance", anim_blend)

# at the top of _physics_process, after applying gravity:
	if celebrating:
		velocity.x = 0
		velocity.z = 0
		move_and_slide()
		return

# world.gd, in _on_coin_collected, after update_label():
	if score == total:
		get_tree().get_first_node_in_group("player").celebrate()
Tested: after celebrate(), holding W left the velocity at zero and the animation stayed on Dance.

Notice the pattern: a celebrating flag, an early return, and an if-ladder of animations. Add a few more states (attacking, hurt, swimming) and this gets messy fast. That mess is the reason state machines exist, which is coming soon.
