Why start here

The Godot docs recommend starting with 2D because “3D game code is always more complex”. You already program for a living, so we'll start in 3D but keep it tiny.

A Valheim-style Viking and a cyberpunk mercenary are built the same way in Godot: as a tree of nodes. In the docs' words: “In Godot, a game is a tree of nodes that you group together into scenes.” Once this model clicks, every tutorial you read afterwards gets easier.

Three ideas

Node. “Nodes are the fundamental building blocks of your game.” Each node does one job: a MeshInstance3D draws a shape, a Camera3D renders the view, a DirectionalLight3D acts as a sun.

Scene. A tree of nodes saved to a .tscn file. Scenes are reusable: they “fill the role of both prefabs and scenes in some other game engines.” One player scene, one enemy scene, one level scene that contains the others.

Scene tree. At runtime, all your scenes come together into one big tree. A child node's position is relative to its parent, so moving a parent moves its children too.

The game loop, embedded-style

GDScript “uses an indentation-based syntax similar to languages like Python” but is “entirely independent from Python”. Type hints like delta: float are optional but catch errors earlier.

You know the superloop: while(1) { read_inputs(); update(); }. Godot runs that loop for you and calls your node's _process(delta) once per frame. delta is “the time elapsed in seconds since the previous call”.

Frame rate isn't fixed. It changes between machines and from moment to moment. So you never move “3 units per frame”. You move 3 * delta, which works out to 3 metres per second whatever the frame rate. The docs are blunt about it: “you should always multiply a speed value by delta”.

Build it

  1. Run godot. In the Project Manager, click Create. Name it first-steps, put it in ~/learning/gamedev/projects/, keep the Forward+ renderer, and create it.
  2. In the Scene dock (top left), click 3D Scene. This creates a Node3D root. Double-click it and rename it Main.
  3. With Main selected, press Ctrl+A (Add Child Node), search for MeshInstance3D, and create it. Rename it Cube.
  4. In the Inspector (right), find Mesh, click <empty> and choose New BoxMesh. A 1 m cube appears.
  5. Select Main again and add a Camera3D. In the Inspector, open Transform and set Position to y = 1, z = 4. Godot is Y-up, 1 unit = 1 metre, so the camera now sits 4 m back and 1 m up, looking toward the cube.
  6. Select Main and add a DirectionalLight3D. Set its Rotation to x = -45 so the “sun” shines down at an angle.
  7. Save with Ctrl+S as main.tscn. Press F6 (Run Current Scene). You should see a lit cube. Close the window.
  8. Right-click Cube → Attach Script → keep the name cube.gd → Create. Replace everything in the editor with the script below.
  9. Press F6. The cube spins, and the arrow keys drive it around.

extends MeshInstance3D

@export var spin_speed := 1.5   # radians per second
@export var move_speed := 3.0   # metres per second

func _process(delta: float) -> void:
	rotate_y(spin_speed * delta)
	var input := Input.get_vector("ui_left", "ui_right", "ui_up", "ui_down")
	position += Vector3(input.x, 0, input.y) * move_speed * delta

ui_left and the others “are predefined in every Godot project”. Later you'll define your own actions, such as jump.

Line by line: extends says which node type this script controls, because “every GDScript file is implicitly a class”. @export exposes a variable in the Inspector. Input.get_vector turns four actions into a 2D vector capped at length 1, so diagonal movement isn't faster. You map its screen-style X/Y onto the ground plane, X/Z, because Y is up. Up arrow gives y = -1, which becomes -Z, and Vector3.FORWARD is (0, 0, -1): away from the camera.

Experiments: predict first, then run

Write down your prediction before each run. If the result surprises you, you've just learned something.

1. Select Cube. In the Inspector, set Spin Speed to 6.28. How long will one full turn take?

Show answerAbout one second. Angles in code are radians, and a full turn is 2π ≈ 6.28. The Inspector shows Rotation in degrees for humans, but methods take radians.

2. Add a second MeshInstance3D with a BoxMesh as a child of Cube (not of Main). Set its position to x = 1.5. What will it do when you run?

Show answerIt orbits the big cube and follows it when you drive. A child's transform is relative to its parent, so the parent's spin and movement carry the child along. That's how a sword stays in a character's hand.

3. Delete * delta from the rotate_y line and run. What happens, and why? (Put it back afterwards.)

Show answerIt spins wildly: 1.5 radians per frame, so 90 radians per second at 60 fps and more on a faster machine. The speed now depends on the machine. That's exactly the bug delta prevents.
