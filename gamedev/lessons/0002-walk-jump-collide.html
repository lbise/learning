Why are speeds multiplied by delta?

Show answerFrames take different amounts of time. speed * delta gives the distance for this frame, so the motion per second is the same at any frame rate.

What's the difference between a node and a scene?

Show answerA node is one building block. A scene is a saved, reusable tree of nodes.

Why physics now

In Valheim, almost every moment involves the physics engine: walking up a slope, landing a jump, bumping into a tree, a log rolling downhill. Your cube from Lesson 1 had none of that. It was a picture you moved by hand, so it would glide straight through a wall. Today you'll give the game things that are solid.

Four kinds of collision object

The docs page describes the 2D versions. The 3D nodes (…3D) behave the same way.

Godot has four kinds of collision object. Picking the right one is most of the design work:

NodeMoved byUse for
StaticBody3DNothing. It's “not moved by the physics engine”Floors, walls, trees, crates you stand on
CharacterBody3DYour code: “all movement and collision response must be implemented in code”The player and enemies
RigidBody3DThe physics engine: you apply forces, it computes the motionBarrels, falling rocks, ragdolls
Area3DNothing. It only detects overlapsPickups, trigger zones, water

Visuals and collision are separate. A body is invisible to physics until it has a collision shape: “In order to detect collisions, at least one Shape … must be assigned to the object.” So every solid thing is a small tree: a body, a CollisionShape3D (what physics sees), and a MeshInstance3D (what you see).

Player (CharacterBody3D) ← script     Crate (StaticBody3D)
├─ CollisionShape3D  (capsule)          ├─ CollisionShape3D  (box)
├─ MeshInstance3D    (capsule)          └─ MeshInstance3D    (box)
└─ Camera3D

Velocity, not position

Physics runs at “a fixed rate (a default of 60 iterations per second)”, separate from the frame rate. That's why movement code goes in _physics_process.

With a CharacterBody3D you don't write to position. You set velocity (metres per second) and call move_and_slide(). It “moves the body based on velocity. If the body collides with another, it will slide along the other body rather than stop immediately”, and it “uses the physics step's delta value automatically”.

Think of it as integrating twice. Gravity is an acceleration, so you integrate it into velocity yourself: velocity += gravity * delta. Velocity becomes position inside move_and_slide(). The docs warn about the classic bug: “A common mistake is setting this property to the desired velocity multiplied by delta.”

Build it

Keep working in your first-steps project.

A. Input actions

  1. Project → Project Settings → Input Map tab. Type move_forward in the “Add New Action” field and click Add.
  2. Click the + next to move_forward, press W, and click OK.
  3. Do the same for move_back (S), move_left (A), move_right (D) and jump (Space). Close the window.

B. The crate scene

  1. Scene → New Scene. Choose Other Node and pick StaticBody3D. Rename it Crate.
  2. Add a child CollisionShape3D. In the Inspector, set Shape → New BoxShape3D (1 m by default) and Position y = 0.5, so the crate sits on the ground instead of half inside it.
  3. Add a child MeshInstance3D to Crate. Set Mesh → New BoxMesh and Position y = 0.5.
  4. Save as crate.tscn.

C. The player scene

  1. New scene, root CharacterBody3D, renamed Player.
  2. Add CollisionShape3D: New CapsuleShape3D, Position y = 1. The default capsule is 2 m tall, so this puts the feet at the player's origin.
  3. Add MeshInstance3D: New CapsuleMesh, Position y = 1.
  4. Add Camera3D as a child of Player: Position y = 3, z = 6, Rotation x = -20. Because it's a child, it will follow the player (remember the orbiting cube).
  5. Attach a script to Player (player.gd). Replace its contents with the code below, then save as player.tscn.

extends CharacterBody3D

@export var speed := 5.0          # metres per second
@export var jump_velocity := 4.5  # metres per second, upward

func _physics_process(delta: float) -> void:
	# Integrate acceleration into velocity: this one needs delta.
	if not is_on_floor():
		velocity += get_gravity() * delta

	if Input.is_action_just_pressed("jump") and is_on_floor():
		velocity.y = jump_velocity

	var input := Input.get_vector("move_left", "move_right",
			"move_forward", "move_back")
	velocity.x = input.x * speed
	velocity.z = input.y * speed

	# Velocity into position, with collisions. Delta applied inside.
	move_and_slide()

get_gravity() returns world gravity (9.8 m/s² down by default), plus any overrides from Area3Ds, which is handy for a low-gravity zone later.

is_on_floor() reports whether the last move_and_slide() touched a floor. is_action_just_pressed is true only on the tick the key goes down, not while it's held.

D. The world

  1. New scene, 3D Scene root, renamed World. Add a DirectionalLight3D with Rotation x = -45.
  2. Add a StaticBody3D named Floor, then give it a CollisionShape3D (BoxShape3D) and a MeshInstance3D (BoxMesh). Set both sizes to 20 × 1 × 20 and both positions to y = -0.5. Size belongs to the shape or mesh, not to the node: in the Inspector, click the BoxShape3D / BoxMesh field itself to expand it, and Size (x, y, z) appears underneath. Position is on the node, under Transform. Change Size, never the node's Scale: the docs say “be careful to never scale your collision shapes”.
  3. Drag player.tscn from the FileSystem dock (bottom left) onto World. This creates an instance of your scene.
  4. Drag crate.tscn in the same way and set its Position x = 3, so it doesn't spawn inside the player. With the crate selected, press Ctrl+D a few times to duplicate it, and move the copies around with the gizmo. Put one crate directly on top of another (y = 1).
  5. Save as world.tscn and press F6. Walk, jump, and bump into things.

Experiments: predict first, then run

1. Add a plain MeshInstance3D with a BoxMesh to World, with no body and no shape. What happens when you walk into it?

Show answerYou walk straight through it. Physics never sees a mesh, only collision shapes. When something is “invisible but solid” or “visible but ghostly”, the cause is nearly always here.

2. Use the physics you already know. With jump_velocity = 4.5 and g = 9.8 m/s², how high does the player's origin (the feet) rise? Can you get onto a 1 m crate? What jump velocity would you need to land on the 2 m stack? Work it out, set it on the Player instance in the Inspector, and test.

Show answerh = v²/2g = 4.5²/19.6 ≈ 1.03 m, just enough for one crate. For 2 m: v = √(2·9.8·2) ≈ 6.3 m/s, so try 6.5 for some margin. When I measured it in Godot 4.7, the peak at 4.5 m/s was about 1.07 m, slightly above the analytic value. The engine steps velocity and position in discrete 1/60 s ticks rather than integrating continuously, which you'll recognise from fixed-step control loops.

3. Open crate.tscn, select its MeshInstance3D, and under Surface Material Override (or Mesh → Material) create a New StandardMaterial3D. Set its Albedo → Color to brown and save. How many crates in world.tscn change colour?

Show answerAll of them. Each crate in the world is an instance of one scene, so editing the scene updates every copy. That's how you'll later build one enemy and place fifty.
