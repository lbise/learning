Warm-up: from memory

Blender's up axis vs Godot's, and who converts between them?

Show answerBlender is Z-up and Godot is Y-up. The glTF exporter's +Y Up option converts.

From Lesson 2: what does the Godot documentation say about scaling collision shapes?

Show answerNever do it. Change their size properties instead. You'll need this again in part ③.

From Lesson 8: in Blender, what's the difference between an object and its mesh data?

Show answerThe object holds the location, rotation and scale (like a Node3D). The mesh data holds the actual shape (like a Mesh resource). G/R/S in Object Mode change the object, not the data.

① Worked example: the coin

Why preparation matters

An exported glTF keeps Blender's object structure: each object becomes a node with its transform. If your coin sits 3 m to the side, rotated 90°, Godot gets a node 3 m to the side, rotated 90°, inside your Coin scene. Three habits prevent most problems:

HabitBlenderWhy it matters in Godot
Object at the world originAlt+G: “move the selection back to the coordinates (0, 0, 0)”Otherwise the model is offset from your scene's origin, and from its collision shape.
Transforms appliedCtrl+A → All Transforms: “The object transformation coordinates are transferred to the object data.”The shape lives in the mesh and the node arrives clean (no rotation, scale 1). No hidden scale ends up under your physics bodies.
Export only the selectionExport option Include → Limit to → Selected ObjectsOtherwise coin.glb also contains your tree, and anything else in the file.

Blender side

  1. Open props.blend. Click the Coin so it's the only thing selected.
  2. Alt+G. The coin jumps back to the world origin (it was 3 m out on X). It'll overlap the tree for now, which is fine.
  3. Ctrl+A → All Transforms. Check the Sidebar (N): rotation is now 0, 0, 0 but the coin still stands upright, because the rotation has moved into the mesh.
  4. File → Export → glTF 2.0. On the right: Format .glb. Under Include, tick Limit to: Selected Objects. Under Transform, keep +Y Up ticked (the default).
  5. Save it as coin.glb in a models/ folder inside your Godot project.

Godot side

  1. Switch to Godot. The FileSystem dock shows models/coin.glb, imported automatically.
  2. Open coin.tscn. Delete the old MeshInstance3D (the CylinderMesh with rotation x = 90).
  3. Drag coin.glb onto the Coin root. That's all: no rotation needed, because Blender's +Z-up and your applied rotation become an upright coin in Godot.
  4. Run the world. Every coin is now yours: same size, same spin, gold material from Blender.

I ran this whole pipeline headless: Blender 5.2.2 → .glb → Godot 4.7.2. The imported coin is 0.8 × 0.8 × 0.1 m (standing upright, facing Z), and its material arrived as a StandardMaterial3D named Gold with metallic 1.0 and roughness 0.3.

The iteration loop: change the coin in Blender, export again over the same file, and Godot reimports it. Every coin instance in every level updates, the same way your crates did when you edited crate.tscn.

Predict, then check

1. You skip Alt+G and export the coin while it's still 3 m out on X. What do players experience?

Show answerThe visible coin floats 3 m away from where it can be picked up. The Area3D's sphere is still at the Coin scene's origin. Visuals and collision are separate (Lesson 2), and here they've drifted apart.

2. You forget Selected Objects. What's inside coin.glb?

Show answerEverything in the file: coin, trunk, foliage, and the default camera and light if they're still in the scene (the exporter's Include panel decides what goes in). Every coin in your level would carry a tree.

② Completion: the tree

The tree is two objects (trunk and foliage) with the trunk's base on the ground. For a game prop you want one object whose origin is at the base of the trunk, so that placing it at y = 0 in Godot puts it on the ground, the same way the crate scene worked. Fill in the blanks, then check:

  1. Join: click Foliage, then Shift-click Trunk so the trunk is selected last. Press Ctrl+J. Join “merges all selected objects into the last selected Active object”. Rename the result Tree. Blank 1: which object's origin does the joined object keep?
  2. Origin to the base: Shift+S → Cursor to World Origin. Your trunk's base is already at (0, 0, 0), so now use Object → Set Origin → ______. Blank 2.
  3. Clean transforms: Ctrl+A → ______. Blank 3.
  4. Export tree.glb into the same models/ folder, with the same three export settings as the coin.

Answers

Show answers 1. The active (last-selected) object's, so the trunk's centre at (0, 0, 0.75): not at the base, which is why step 2 exists. 2. Origin to 3D Cursor: “Moves the origin of the model to the position of the 3D cursor.” 3. All Transforms.
Tested: the imported tree's bounds start at y = 0 and are 3.3 m tall, and it keeps two materials, Bark and Leaves, as two surfaces of one mesh.

Two shortcuts you may meet later. Godot can import .blend files directly by “calling Blender to export to glTF in a transparent manner”. And an object named with a -col suffix gets a collision shape generated “using the same geometry as the mesh … slow, but accurate”. Doing it by hand first tells you what those shortcuts automate.

③ On your own: a solid tree, then a forest

Everything you need comes from Lessons 2 and 3 plus today. Build a reusable tree.tscn and plant it around your level.

  1. tree.tscn's root is the right collision object type for something that never moves (Lesson 2).
  2. The player can't walk through the trunk. Choose a collision shape and size that fits it. Do you want the foliage to be solid too? Decide, and know why.
  3. At least 8 trees in world.tscn, placed around the coins. Vary them by rotating around Y so they don't all look identical.
  4. Some trees are a different size, without scaling any collision shape.
  5. Back the player up against a trunk: the camera should pull in rather than end up inside it. Why does that already work?

Hint: size variety without scaling collision

Show hintScaling the StaticBody3D scales its shape, which the docs warn against. Two clean options: make a second tree in Blender (taller, or wider) and export it as tree_tall.glb with its own scene and correctly sized shape; or keep one scene and use the shape's own Radius/Height fields for a variant. Variety from rotation alone already goes a long way.

Solution sketch

Show solution 
Tree (StaticBody3D)
├─ tree (instance of tree.glb)        origin at the base, no transform
└─ CollisionShape3D  CylinderShape3D  radius ≈ 0.2, height 1.5, position y = 0.75
Trunk-only collision lets the player brush through the low branches, which feels fine for a pine. A taller cylinder or a ConeShape-like approximation makes the whole tree solid. The camera already pulls in because the SpringArm3D casts against physics shapes (Lesson 4), and your trunk now has one.
