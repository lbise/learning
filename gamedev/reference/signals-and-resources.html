Signals

# declare (custom)
signal collected
signal damaged(amount: int)

# emit
collected.emit()
damaged.emit(10)

# connect: signal.connect(callable)
body_entered.connect(_on_body_entered)
coin.collected.connect(_on_coin_collected)

The emitter doesn't know who listens (the observer pattern). Handler names follow the convention _on_<node>_<signal>.

Area3D pickups

extends Area3D
signal collected

func _ready() -> void:
	body_entered.connect(_on_body_entered)

func _on_body_entered(body: Node3D) -> void:
	if body.is_in_group("player"):
		collected.emit()
		queue_free()

body_entered fires for any physics body, so filter with a group. queue_free() deletes the node at the end of the frame.

Sources: Area3D, Node

Who wires the signal?

The node that knows both sides. Usually that's the parent or level, never the reusable child.

# world.gd: emits AND wires (dependency injection)
signal all_coins_collected

func _ready() -> void:
	all_coins_collected.connect($Player.celebrate)
World calls player.celebrate()OK: the parent calls down
Player finds World and connects itselfAvoid: the child now depends on its level
World emits, World (or the editor's Node dock) connectsBest: neither script needs the other

Name signals in the past tense: item_collected, all_coins_collected.
